# ابزار کشف و آزمون خودکار وب‌سرویس‌های فرانت‌اند
### Frontend API Discovery & Automated Testing Tool (Antigravity Skill)

[![Node.js](https://img.shields.io/badge/node-%3E%3D18.0.0-brightgreen.svg)](https://nodejs.org/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Zero Dependencies](https://img.shields.io/badge/dependencies-0-blue.svg)](#)

ابزاری سبک، مستقل و بدون نیاز به نصب هیچ‌گونه وابستگی خارجی (`Zero Dependencies`) برای تحلیل کدهای فرانت‌اند، کشف تمام فراخوانی‌های شبکه، تولید خودکار مستندات `apis.md` و راه‌اندازی پنل وب محلی جهت آزمون امن وب‌سرویس‌ها.

این ابزار هم به عنوان **مهارت اختصاصی ایجنت (Agent Skill)** و هم به صورت **ابزار خط فرمان مستقل (CLI)** قابل استفاده است.

---

## قابلیت‌های کلیدی

- **اسکن خودکار و صفر-کانفیگ**: شناسایی آدرس‌های پایه از فایل‌های `.env*` و کانفیگ‌های `vite` یا `next`، به همراه استخراج تمام مسیرهای کلاینت‌های شبکه (Axios, Fetch, Ky, RTK Query).
- **مرتب‌سازی ترتیبی وابستگی‌ها (DAG)**: شناسایی تقدم و تاخر منطقی درخواست‌ها (مثلاً دریافت فهرست قبل از ایجاد، یا ایجاد قبل از ویرایش/حذف).
- **تولید خودکار مستندات `apis.md`**: ایجاد خروجی خوانا و ساختاریافته از وب‌سرویس‌ها، هدرها، متدها و بدنه‌های نمونه.
- **پنل وب تعاملی محلی (`http://localhost:3456`)**: با طراحی مدرن، واکنش‌گرا، راست‌چین (RTL فارسی) و قابلیت تغییر تم تاریک و روشن.
- **رفتار امن پیش‌فرض (Safe by Default)**: تیک‌خوردن خودکار متدهای ایمن (`GET`, `HEAD`) و غیرفعال بودن اولیه متدهای تغییردهنده (`POST`, `PUT`, `DELETE`).
- **پشتیبانی از ورود و کد دومرحله‌ای (2FA / OTP)**: امکان ورود توکن Bearer، کلیدهای دسترسی سفارشی و فیلد تعاملی کد دومرحله‌ای در پنل.
- **تزریق خودکار پارامترهای وابسته (Chaining)**: استخراج خودکار شناسه‌ها (`id`) و توکن‌ها از پاسخ مراحل قبل و قرار دادن آن‌ها در مسیر درخواست‌های بعدی (مانند `/api/orders/:id`).
- **ذخیره‌سازی ایزوله خروجی‌ها**: ذخیره هر پاسخ دریافتی در قالب یک فایل مستقل JSON در دیسک (`.api-tester/responses/*.json`).
- **پایش زنده و عیب‌یابی هوشمند (SSE)**: استریم بلادرنگ وضعیت اجرای هر مرحله و نمایش تحلیل هوشمند خطاها (۴۰۱، ۴۰۴، ۴۲۲، ۵۰۰ یا خطای اتصال) به همراه راهکار پیشنهادی.

## راهنمای نصب و راه‌اندازی (Installation)

بسته به شیوه کاری خود، یکی از ۳ روش زیر را برای نصب انتخاب کنید:

### روش ۱: نصب سراسری برای ایجنت هوش مصنوعی (پیشنهادی)
با این روش، مهارت روی سیستم شما ثبت شده و در **تمام پروژه‌های فرانت‌اند** در دسترس ایجنت خواهد بود:

**ویندوز (در محیط PowerShell):**
```powershell
git clone https://github.com/mahdiasd/api-discovery-tester.git "$HOME\.gemini\antigravity\skills\api-discovery-tester"
```

**مک و لینوکس (Bash/Zsh):**
```bash
git clone https://github.com/mahdiasd/api-discovery-tester.git ~/.gemini/antigravity/skills/api-discovery-tester
```

---

### روش ۲: نصب در سطح یک پروژه خاص (Project-Level)
اگر می‌خواهید این مهارت تنها در مخزن یک پروژه خاص قرار گیرد:

```bash
# رفتن به ریشه پروژه فرانت‌اند
cd /path/to/your/frontend-project

# ایجاد دایرکتوری مهارت‌ها و کلون کردن
mkdir -p .agents/skills
git clone https://github.com/mahdiasd/api-discovery-tester.git .agents/skills/api-discovery-tester
```

---

### روش ۳: اجرای مستقیم بدون نصب (CLI / NPX)
بدون نیاز به ثبت مهارت، می‌توانید آن را به صورت مستقیم در ریشه هر پروژه فرانت‌اند اجرا کنید:

```bash
# اجرا با npx مستقیم از مخزن گیت‌هاب
npx https://github.com/mahdiasd/api-discovery-tester

# یا در صورت کلون بودن پروژه:
node .agents/skills/api-discovery-tester/bin/cli.js
```

## نحوه استفاده (Usage)

### گام ۱: اجرای دستور
در محیط گفتگو با ایجنت در پروژه فرانت‌اند خود، دستور زیر را ارسال کنید:

```text
/api-tester-start
```
*(یا به زبان طبیعی بنویسید: «وب‌سرویس‌های پروژه رو اسکن و پنل تست رو باز کن»)*

### گام ۲: بازبینی در پنل وب
1. مرورگر شما روی آدرس `http://localhost:3456` باز می‌شود.
2. آدرس پایه (`Base URL`) و نوع احراز هویت را در صورت نیاز ویرایش کنید.
3. در صورت نیاز به توکن یا کد 2FA، آن را در فیلدهای مربوطه وارد نمایید.
4. وب‌سرویس‌های مدنظر خود را علامت بزنید (متدهای `GET` از قبل انتخاب شده‌اند).

### گام ۳: شروع تست و دریافت نتایج
1. روی دکمه **«▶ شروع تست»** کلیک کنید.
2. پیشرفت تست و نتایج به صورت زنده نمایش داده می‌شوند.
3. فایل‌های پاسخ در مسیر `.api-tester/responses/` ذخیره شده و مستندات در فایل `apis.md` در ریشه پروژه در دسترس شماست.

## ساختار فایل‌های ذخیره‌شده

```text
your-frontend-project/
├── apis.md                       # مستندات کامل وب‌سرویس‌های کشف‌شده
└── .api-tester/
    ├── discovery.json            # مانیفست خام اطلاعات و وب‌سرویس‌های پروژه
    └── responses/                # پوشه پاسخ‌های مستقل JSON
        ├── 1_GET_users.json
        ├── 2_POST_users.json
        └── 3_GET_users_id.json
```
